## 🤔 이게 뭔가요?

**Korea Stats MCP**는 AI 비서(Claude, ChatGPT 등)가 **대한민국 공식 통계**를 직접 조회할 수 있게 해주는 도구입니다.

### 이런 질문을 할 수 있어요:

| 질문 예시                     | 얻을 수 있는 정보    |
| ----------------------------- | -------------------- |
| "한국 인구가 몇 명이야?"      | 최신 인구 통계       |
| "서울 출산율 추이 보여줘"     | 10년간 출산율 그래프 |
| "부산과 대구 실업률 비교해줘" | 지역별 비교 데이터   |
| "아파트 가격 통계 찾아줘"     | 관련 통계표 목록     |

### 데이터 출처

- [KOSIS 국가통계포털](https://kosis.kr): 공식 통계표, 분류·항목 메타데이터, 지표 정의와 값
- [공공데이터포털 상권정보](https://www.data.go.kr/data/15012005/openapi.do): 공개 사업체 원자료
- [MDIS](https://mdis.mods.go.kr): 공개 조사·dataset(조사자료 묶음)·변수·코드북 메타데이터

자료별 수록 시점·갱신 주기·접근 조건이 다릅니다. 조회 시각이 자료의 기준 시점이나 전체 취득 완료를 뜻하지 않습니다.

## 💻 설치하기

### 키 없이 원격 서버 사용하기

MCP 클라이언트에 `https://korea-stats-mcp.vercel.app/mcp`를 등록하면 됩니다. 사용자 KOSIS 키나 KOSIS 회원가입은 필요하지 않습니다. 운영자가 서버 환경변수로 인증을 관리합니다.

### Claude Code와 Codex 연결

```bash
# Claude Code
claude mcp add --scope user --transport http korea-stats https://korea-stats-mcp.vercel.app/mcp
claude mcp get korea-stats

# Codex
codex mcp add korea-stats --url https://korea-stats-mcp.vercel.app/mcp
codex mcp get korea-stats
```

원하는 클라이언트의 명령을 실행한 뒤 새 세션을 시작하세요. 두 클라이언트의 기본 HTTP 연결을 사용하며 별도 `mcp-remote` 설치나 사용자 KOSIS 키는 필요하지 않습니다. 같은 이름의 서버가 이미 있으면 기존 설정을 먼저 확인합니다.

아래 로컬 설치 절차는 직접 서버를 실행하려는 사용자를 위한 선택 경로입니다.

### 준비물

1. **Claude Code** 또는 **Codex CLI**
2. **Node.js 20** 이상 (로컬 서버 실행; 개발용 Inspector는 Node.js 22.19 이상)
3. **KOSIS API 키는 선택 사항**입니다. 없으면 공개 원격 서버를 이용하고, 설정하면 KOSIS를 직접 조회합니다.

### Step 1: 직접 조회할 때만 KOSIS API 키 발급받기

1. [KOSIS 공유서비스](https://kosis.kr/openapi) 접속
2. 회원가입 (무료)
3. "활용신청" 클릭 → 자동 승인
4. "신청현황"에서 **인증키** 복사

### Step 2: 프로젝트 설치

```bash
# 1. 저장소 클론
git clone https://github.com/Dayoooun/korea-stats-mcp.git
cd korea-stats-mcp

# 2. 의존성 설치
pnpm install --frozen-lockfile

# 3. 선택: 공개 서버를 거치지 않고 직접 조회할 경우만 .env에 본인 키 설정
# 기본 실행에는 .env나 API 키가 필요하지 않습니다.

# 4. 빌드
pnpm run build
```

### Step 3: 로컬 빌드를 클라이언트에 연결하기

원격 연결 대신 로컬 서버를 실행할 때만 등록합니다.

```bash
# Claude Code
claude mcp add --scope user --transport stdio korea-stats-local -- node /절대경로/korea-stats-mcp/dist/index.js

# Codex
codex mcp add korea-stats-local -- node /절대경로/korea-stats-mcp/dist/index.js
```

### Step 4: 새 세션에서 실제 조회 확인

Claude Code 또는 Codex의 새 세션에서 “korea-stats로 부산 동래구 2025년 인구를 조회해줘”라고 요청하고, 실제 MCP 도구 호출과 반환 출처를 확인하세요. 모델이 답변만 생성한 것을 연결 성공으로 취급하지 않습니다.

## 추가 자료 조회 (개발본)

현재 소스는 14개 도구를 등록합니다. 공개 원격 서버와 npm 버전은 배포된 도구만 제공하며, 키 없는 로컬 실행도 원격 배포본을 따릅니다.

`search_statistics`와 `get_recommended_statistics`는 조회 후보를 찾는 도구입니다. 검색 결과의 목록 코드 `VW_CD`는 수록주기가 아니므로 `periodType: ""`은 주기 미확정을 뜻합니다. 수록 종료 시점 `END_PRD_DE`도 제공기관 갱신 시각이 아니므로 검색 결과의 `lastUpdated`로 표시하지 않습니다. 실제 주기는 `get_table_info`의 `infoType: "PRD"`로 확인하세요. 추천 표의 이름이나 우선순위만으로 자료 취득·지역 지원·정의의 동일성을 판단하지 않습니다.

분류 안내와 주요 통계표 리소스는 `metadataStatus: "static_reference"`인 정적 참고 자료입니다. `lastUpdatedSemantics`에 표시된 생성일을 공급자 갱신일로 해석하지 마세요. 리소스 URI와 식별자는 유지되지만 실제 공식 목록·차원·자료는 해당 조회 도구에서 확인해야 합니다.

### 공식 분류와 시군구

`get_table_info`에서 통계표의 공식 분류·항목과 다음 페이지 커서를 확인합니다. 지역 지원은 통계표마다 다릅니다. 시군구를 확인할 수 없거나 동명 지역이 여러 곳이면 상위 지역·전국 값으로 대신 답하지 않습니다.

KOSIS 분류코드를 상권 API의 행정구역 코드로 재사용하지 마세요. 같은 지역도 공급자별 코드가 다를 수 있습니다.

중첩된 시군구 전체 이름을 보완하는 자동 대조도 코드가 같다는 이유만으로 성공하지 않습니다. 공식 이름·시도까지 일치해야 하며, 현재 명칭과 과거 경계의 한계 및 운영자 설정은 [README의 지역별 조회 안내](../README.md)를 참고하세요.

연간 요청은 `periodType: "Y"`를 사용합니다. KOSIS가 연간 응답의 `PRD_SE`를 `"A"`로 반환하는 경우 검증·계산에서 `"Y"`와 같은 주기로 해석합니다. `get_statistics_data`의 `data[].periodType`은 `"Y"`이며 `data[].raw.PRD_SE`는 공급자가 반환한 `"A"`를 그대로 보존합니다. 월·분기·알 수 없는 주기를 연간으로 바꾸지는 않습니다.

### 통계자료 이어받기

- `get_statistics_data`에 연·월·분기의 `startPeriod`와 `endPeriod`를 모두 지정하고 `recentCount`는 함께 보내지 않습니다. `pageSize`는 기본 50, 최대 200입니다.
- 공식 메타데이터에서 확인한 코드를 `+`로 연결한 KOSIS 다중 선택식은 그대로 전달합니다. 단일 코드로 오인해 거절하지 않지만, 다중 선택의 전체성을 자동 검증한 것은 아니므로 `validationLevel`은 `unverified`입니다. 원본 식별자와 관측값을 대조하고 전체 페이지를 이어받아야 합니다.
- `hasMore: true`이면 **모든 원래 조회 조건을 유지한 채** `nextCursor`를 `cursor`로 전달합니다. 출력·기간 분할 페이지는 전체 결과가 아니며, `continuationReason: "partition_split"`인 0행 진행 페이지도 이어받아야 합니다.
- 공급자 응답은 4 MiB, 전체 MCP 출력은 32 KiB로 제한합니다. 큰 응답은 기간을 나누어 조회하지만 단일 기간도 크면 `ATOMIC_PERIOD_TOO_LARGE`입니다. 관측 하나가 출력 상한보다 크면 `OUTPUT_ROW_TOO_LARGE`이며 값을 잘라 성공으로 반환하지 않습니다.
- `returnedCount`는 현재 페이지, `emittedCount`는 해당 커서 흐름의 누적 반환 건수입니다. `aggregateRowCount`는 유한 범위 순회가 끝났을 때만 채워지며 공급자 총건수가 아닙니다.
- `completionScope: "requested_period_traversal"`는 요청 기간 순회만 뜻합니다. `providerTotalCount: null`, `providerSnapshot: "unproven"`을 전체 자료·동일 시점 자료로 해석하지 마세요. 분할 후 기간 근거는 각 분할 범위에 한정됩니다.
- 활성 분할 자료가 바뀌면 `RESTART_REQUIRED`로 실패합니다. 이전 페이지와 새 자료를 혼합하지 말고 처음부터 다시 조회하세요. 마지막 페이지도 현재 페이지 관측만 담습니다.
- 최근 조건·한쪽 끝만 지정한 범위·지원 밖 주기는 `completion: "unproven"`입니다. 오류 증거가 크면 `evidenceTruncated`와 실제 관측/반환 증거 건수를 표시하며, 누락된 증거를 전부 받은 것으로 표현하지 않습니다.
- `compare_statistics`와 `analyze_time_series`는 필요한 페이지를 모은 뒤 계산합니다. 한 도구 호출 전체에 64페이지·10,000관측 한도를 적용하며 비교 시점마다 한도를 새로 부여하지 않습니다. 한도 초과·중단 시 부분 관측으로 계산하지 않으며, 수집 중단 시 남기는 오류 증거는 최대 200관측입니다.
- `compare_statistics`에 `periods: ["2015", "2025"]`처럼 시점을 명시하면 두 시점 사이의 변화를 비교합니다. 요청하지 않은 중간 연도까지 요구하거나 채우지는 않습니다. 요청한 시점의 누락·중복은 계속 거부하며, 시점을 명시하지 않은 연속 관측 비교와 `analyze_time_series`는 기간 누락 검사를 유지합니다.
- 분석·비교의 `provenance.sourceUrls`와 `queryList`는 요청한 논리 조회 조건입니다. 캐시·기간 분할까지 포함한 실제 네트워크 호출 이력은 아니며 `upstreamRequestHistory: "not_recorded"`로 구분합니다.
- `queriedAt`·`readAt`는 도구가 관측을 읽은 시각이지 공급자가 자료를 갱신한 시각이 아닙니다. 미제공 정의·분모·경계·공급자 갱신 시각은 `null`이며, 당시 공표값을 임의로 재배분·환산하지 않습니다.
- 출처 진단의 조회 목록은 최대 64개, 관측 식별자는 최대 200개입니다. 원래 개수와 절단 여부를 함께 확인하세요. 계산 실패의 `appliedCalculations`는 비어 있으며 계산 정책을 실제 계산 결과로 표시하지 않습니다.

### 공식 지표

- `search_indicators`: `filters` 안에 `indicatorName`, `indicatorId`, `period` 중 하나 이상을 지정합니다. 페이지는 `page`, `pageSize`입니다.
- 공급자는 이름·ID·주기별 검색 경로가 다릅니다. 복합 조건은 ID → 이름 → 주기 순서로 한 공급자 경로를 선택하고, 나머지 조건은 받은 **현재 페이지 안에서** 적용합니다. `appliedFilters`, `filterScope`, `providerCount`를 확인하세요. 필터 후 빈 페이지도 전체 검색 결과가 없다는 뜻이 아니며, `hasMore`는 `unknown`입니다.
- `get_indicator`: 검색에서 확인한 `indicatorId`와 `kind`를 지정합니다. 정의는 `kind: "definition"`이며 시간 조건을 받지 않습니다.
- 값은 `kind: "values"`와 공식 `indicatorName`을 함께 지정합니다. 이름은 반환 지표와의 일치 검증에 사용하고, 공급자 ID 조회 URL에는 ID만 전달합니다. 시점 조건은 `startPeriod`, `endPeriod`, 공급자 최근 조건은 `recentReference`, `recentCount`입니다. 최근 조건만으로 실제 최신성까지 확인됐다고 해석하지 마세요.
- `jipyoId`, `jipyoNm`, `prdSe`, `strtPrdDe`, `rn`, `srvRn` 등 공급자 필드명을 공용 입력 별칭으로 받지 않습니다. 지표 값의 `startPeriod`는 공급자가 실제 사용하는 `strtPrdDe`로 전달합니다.
- 지표 API에는 `jsonVD=Y`를 지정해 엄격한 JSON을 받습니다. 정의는 공식 `pkAll` 응답의 개념·선정방법·출처 중 실제 제공된 항목만 표시합니다. 목록·값의 원본 ID 필드는 `statJipyoId`, 정의의 원본 ID 필드는 `jipyoId`이며 원문 필드를 덮어쓰지 않습니다. 검색되는 지표라도 정의가 없으면 정의 조회는 실패할 수 있습니다.

### 공개 사업체 원자료

`search_businesses`는 `regionType`·`regionCode` 또는 `industryType`·`industryCode` 쌍으로 조회합니다. 공급자의 공식 코드를 사용하고 페이지별 반환 건수·총건수·`hasMore`를 확인하세요. 한 페이지를 받았다고 전체 사업체를 취득한 것은 아닙니다.

공개 서버 운영자는 승인된 `DATA_GO_KR_SERVICE_KEY`를 서버 환경변수로 관리합니다. 이용자 개인의 발급·회원가입을 필수로 요구하지 않습니다.

### MDIS 공개 메타데이터

1. `search_microdata`의 `query`, `page`, `pageSize`로 조사를 찾습니다.
2. 반환된 `survId`, `itmDiv`로 `get_microdata_info`를 호출해 실제 선택 가능한 dataset을 확인합니다.
3. 그 결과에서 `mappId`, `survAreaId`, `ofrSurvYm`를 명시해 변수 정의를 조회합니다. 첫 dataset을 자동 선택하지 않습니다.
4. `detailPage`는 MDIS의 상세 탐색 문맥이며 dataset 페이지라는 뜻이 아닙니다. `variablePage`와 `pageSize`는 조회된 변수 배열을 나누는 별도 페이지입니다.
5. 코드북 확인이 필요하면 `downloadCodebook: true`를 지정합니다. 반환값은 파일 내용이 아니라 출처·바이트 수·해시 등의 확인 정보입니다. `validation.level: "header-only"`는 파일 형식·파일 헤더까지만 확인한 것이며, 워크시트 본문이 정상적으로 읽히는지까지 검증하지 않습니다.

`get_microdata_info`의 기본 `metadataSource: "survey_detail"`은 `surveyId`, `areaId`, `year`, `page`, `includeCodebook` 별칭을 받지 않습니다. `pmsSurvAreaId`는 두 모드 모두 서버가 공식 화면에서 추출하며 호출 인자가 아닙니다. 변수 식별자 근거가 부족하면 `variableIdentityStatus`는 `unverified`(미검증)입니다.
`search_microdata` 검색어 필드는 `query`이며 `keyword` 등 선언되지 않은 필드를 거부합니다. `search_businesses`도 알 수 없는 필드를 거부하므로, 필터 오타를 무시한 더 넓은 검색 결과를 성공으로 반환하지 않습니다.

이 도구는 공식 API가 아니라 공개 웹 `adapter`(공개 웹 응답을 MCP 도구 형식으로 연결하는 모듈)입니다. 공개 메타데이터 탐색과 연구자 원자료 이용 승인은 별개입니다. 연구자 로그인·일반 다운로드·RAS·SDC 신청과 분석은 본인 환경의 공식 경로에서 진행하며, 서버에 연구자 비밀번호·쿠키를 전달하지 않습니다.

### 인가용 자료의 공개 변수·코드북 탐색

일반 조사 상세와 서비스 유형별 항목 화면은 다른 공식 경로입니다. 인가용 자료에 일반 조사 상세의 식별자나 빈 공간 코드를 임의로 넣지 않습니다.

1. `get_microdata_info`에 `metadataSource: "service_items"`, `query: "기업사업체연계정보"`, `page: 1`, `pageSize: 20`을 전달해 실제 서비스 항목을 찾습니다.
2. 반환된 항목의 `mappId`, `itmDiv`, `ofrSurvYm`를 선택해 같은 모드로 다시 조회합니다. 이 모드에서는 `survId`, `survAreaId`, `detailPage`를 보내지 않습니다.
3. `variablePage`로 공개 변수 정의를 이어받고 `downloadCodebook: true`로 실제 코드북의 바이트·해시·헤더를 확인합니다. 카탈로그의 숫자는 제공 항목 수이며, 팝업의 변수별 `O` 제공 표시와 구분합니다. 공식 화면의 `-`를 연도나 0으로 바꾸지 않습니다.
4. 공식 팝업·다운로드 양식의 공간 식별자가 빈 경우에만 그 빈 값을 서버가 그대로 전달합니다. 공간 해상도가 공표되지 않았다는 뜻이며 전국 자료라는 뜻은 아닙니다.

공개 변수·코드북 확인은 인가용 원자료 취득이나 이용 승인과 다릅니다. 연구계획·예상 결과표 제출, 심사·비용·분석·반출은 공식 RAS/SDC 경로에서 사용자가 처리합니다. 서버는 연구자 로그인·쿠키·인가용 레코드를 수집하지 않습니다.

MDIS의 `TIMEOUT`·`NETWORK_ERROR`에는 `diagnostics`(진단 정보 — 실패한 요청 단계와 안전한 경로 정보)가 포함됩니다. `phase: "request"`는 응답 헤더를 기다리는 단계, `"body"`는 응답 본문을 읽는 단계입니다. `pathname`은 확인된 공개 경로만 표시하며, URL의 세션 식별자·쿼리와 쿠키 값은 제외합니다. `cookiePresent`·`refererPresent`는 해당 헤더의 존재 여부일 뿐 연구자 로그인이나 이용 승인 증거가 아닙니다. 카탈로그 전송 실패를 팝업·코드북 실패로 해석하지 마세요.

운영 로그는 `stderr`(표준 오류 출력 — stdio MCP 응답과 분리된 진단 채널)에 제한된 JSON 이벤트로 기록됩니다. 캐시 결과·HTTP 요청 종료와 KOSIS 요청 종류·소요 시간·관측한 응답 바이트 수만 포함하며, 질문 전문·키·쿠키·인증 헤더·URL·세션 식별자는 기록하지 않습니다. KOSIS `provider_outcome`의 `rate_limited`는 HTTP 429, `auth_rejected`는 HTTP 401/403입니다. 로컬 키가 없어 요청하지 않은 경우 `auth_missing`과 `attempts: 0`, 실제 요청은 `attempts: 1`이며 자동 재시도는 하지 않습니다. 응답을 읽지 않았거나 바이트 수를 안전하게 표시할 수 없으면 `responseBytes`는 생략합니다. 이 이벤트의 소요 시간은 개별 요청 관측값이며, 충분한 동일 조건 표본 없이 p95 성능 보장으로 해석하지 않습니다.

## 운영자용 검증·배포·롤백

### 승격 전 확인

1. 설치 아카이브의 SHA-256, 패키지 버전, 실제 설치 경로, 배포 ID와 소스 해시를 같은 후보에 묶습니다. 저장소는 `pnpm-lock.yaml`과 frozen install을 사용하며, 별도 npm 소비자 설치 검증을 저장소의 다른 lockfile로 대체하지 않습니다.
2. `admission`(출시 승인 검사 — 정해진 필수 사례와 실제 증거를 대조하는 검사)은 `tests/requiredCases.ts`의 누적 **R1 12개 → R2 34개 → R3 48개** 순서를 따릅니다. 각 단계의 필수 ID가 모두 실행·통과하고 실패·skip·미실행·누락이 0이어야 합니다. 앞 단계가 실패하면 다음 단계 승격을 중단합니다. 일반 live 검사에서 34개가 통과했다는 사실은 R2 통과가 아닙니다.
3. 단계·후보·버전·대상 URL에 맞는 실제 증거가 필요합니다. 설치/배포 SDK 증거, KOSIS 노출 키의 폐기·교체, **Claude Code와 Codex 각각의 실제 연결·페이지 순회**, 상권 자료 취득, 익명 HTTP 검사를 확인합니다. M06은 두 클라이언트 각각 3회 이상의 성공 연결, 10개 이상의 서로 다른 메타데이터 페이지, 메타데이터에 근거한 후속 자료 조회와 프로토콜 오류 0건을 요구합니다. 한 클라이언트만 성공하거나 Inspector·직접 SDK 호출만 성공한 것으로 대신하지 않습니다. 증거는 `KOREA_STATS_MCP_CLIENTS_RECEIPT_PATH`로 지정합니다. 과거 키 재사용은 폐기를, 보호 우회 헤더가 붙은 preview는 익명 접근을 대신하지 않습니다.
4. 동일 조건 코호트의 `p95`(95번째 백분위 응답 시간)를 비교할 수 있을 때 기준선의 2배를 넘으면 승격을 중단합니다. 조건·표본이 부족하면 비교 불가로 기록하며 개별 시험 시간으로 개선율을 만들지 않습니다. 오답이나 키 노출은 한 건이라도 승격 중단 사유입니다.
5. 운영자 승인과 인증이 준비된 뒤 검증한 아카이브를 게시하고 검증한 배포를 승격합니다. 로컬 빌드·커밋·보호된 preview 성공만으로 공개 서비스가 교체됐다고 보고하지 않습니다. 이용자에게 API 키 발급·회원가입·로그인을 새로 요구하지 않습니다.

### 실제 배포 후 확인

- 공개 URL과 게시된 npm 버전을 각각 확인합니다. 환경변수 없이 시작한 npm/stdio는 공개 원격 서버를 사용하므로, 설치 버전뿐 아니라 실제 원격 `initialize`·`tools/list`와 조회 결과도 대조해야 합니다.
- 익명 `OPTIONS` 200, 그 밖의 비-POST 메서드 405, 정상 JSON POST, 세션 없는 재연결과 메타데이터 이어받기를 실제 공개 대상에서 확인합니다. 지역·기간·단위·출처가 맞는 조회와 미존재 지역 거부도 검사하고, 결과를 아카이브 해시·배포 ID와 함께 남깁니다.

### 안전한 롤백

- 승격 전에 돌아갈 후보의 아카이브 해시·배포 ID·검증 기록과 필요한 운영자 설정을 기록합니다. 비밀 값 자체를 기록에 복사하지 않습니다.
- 노출 키를 포함한 버전, 취약한 의존성, 지역 질문을 전국 값으로 잘못 반환하는 버전은 롤백 대상으로 삼지 않습니다. 안전한 이전 후보가 없으면 그 사실을 명시하며 오래됐다는 이유만으로 자동 복귀하지 않습니다.
- 롤백은 배포 복귀뿐 아니라 npm 소비자 버전과 기본 원격 경로를 함께 확인해야 합니다. 복귀한 공개 대상에서 동일한 익명·지역·메타데이터·출처 검사를 다시 수행합니다.
- 임시 preview 보호 우회 수단은 검증 종료 후 폐기하고 부재를 재확인합니다. 이 정리는 KOSIS 키 폐기 증거와 별개입니다.

## 🔧 문제 해결

### "API 키 오류"가 나와요

1. 키 없는 공개 원격 모드라면 개인 키를 새로 발급받지 말고 공개 서버 상태를 확인하세요. 운영자 자격 증명 오류는 운영자가 해결해야 합니다.
2. 본인 키를 설정한 직접 조회 모드라면 본인 환경의 `KOSIS_API_KEY` 설정을 확인하고 MCP 프로세스를 재시작하세요. 잘못된 개인 키를 공개 원격 모드로 조용히 대체하지 않습니다.
3. 서버 운영자는 대상 배포 환경의 키 설정과 새 배포의 실제 조회를 확인하세요. 키를 채팅·저장소·로그에 붙여 넣지 마세요.

### "통계를 찾을 수 없습니다"가 나와요

1. 다른 키워드로 검색해보세요
   - "출산율" → "출생", "합계출산율"
   - "실업률" → "실업", "고용"
2. 지역명을 추가해보세요
   - "서울 인구", "경기도 GDP"

빠른 조회·추세에서 명시한 시·군·구를 대표 통계표에서 찾지 못하면, `tableDiscovery`에 공식 검색으로 찾은 대체 후보와 원래 표와의 차이를 반환할 수 있습니다. 후보는 최대 5개이며, 조사 출처나 요청 주기가 다르면 `definition_mismatch`입니다. 예를 들어 시도 실업률의 경제활동인구조사와 시군구 실업률의 반기 지역별고용조사는 자동으로 바꾸지 않습니다. 항목 코드가 다르다는 사실만으로 정의가 다르다고 판단하지도 않습니다.

정의·모집단·고정 분류의 동등성이 입증되지 않은 후보는 `metadata_insufficient`이며 `compatibility_not_verified`가 남습니다. 현재 자동 선택은 사전에 공식 근거를 확인한 **연간 출생아수** 한 경로에 한정됩니다. 실제 검색 결과의 `DT_1B81A23`을 원래 `DT_1B8000G`와 대조하여 조사·정의·항목·고정 분류·연간 수록 범위·주석을 확인하고, 공식 지역 계층과 실제 응답 축이 일치할 때만 `matched`로 선택합니다. 지역 코드는 고정 목록이 아닙니다. 확인된 프로필 범위는 2000~2025년이며, 다른 주기나 정의 변경·자료 부족을 전국값으로 대체하지 않습니다.

선택한 표의 응답에 단위가 없으면 그대로 `partial`이며 단위를 지어내지 않습니다. 잠정 출생아 수의 백단위 반올림과 2026년 8월 군지역 코드의 과거 시점 소급 적용 주석도 함께 반환합니다. 빠른 추세는 이 후보의 연간 원관측을 반환하되, 경계·잠정성 근거가 충분하지 않아 `trend: "deferred"`로 파생 추세와 변화율 계산을 보류합니다.

예: `quick_trend({"keyword":"출생아수","region":"부산 동래구","startYear":2023,"endYear":2024})`. 시작·종료 연도는 함께 지정하며 2~20개 연속 연도만 허용합니다. `yearCount`도 지정하면 그 범위의 연도 수와 같아야 합니다. 연도 범위를 생략하면 기존 기본값인 최근 10개 연간 관측을 요청합니다.

`metadataCalls`·`metadataCallBudget`은 메타데이터 요청 범위입니다. 별도의 축 확인용 관측 요청 수는 포함하지 않으며, 자료 전체 취득이나 응답 시간을 보장하지 않습니다. 후보 없음·메타데이터 부족·제공원 오류도 구분하므로, 이를 KOSIS 전체의 시군구 자료 미지원으로 해석하지 마세요.

### 데이터가 이상해요

1. 통계표마다 지역 코드 체계가 다를 수 있습니다
2. AI에게 "get_table_info로 코드 확인해줘"라고 요청하세요
3. 연·월·분기의 명시 범위는 항목·분류별 시작/종료와 내부 누락을 검사합니다. 불완전하면 `response_incomplete`이며 보존 가능한 관측은 `data[].raw`에 남습니다.
4. `recentCount`를 채웠더라도 최신성·전체성은 미검증입니다. 최근 관측 수 부족이나 중복 관측은 실패하며, 결측을 0으로 채우지 않습니다.
5. 큰 통계자료는 위의 유한 기간 이어받기 절차를 사용하세요. 단일 기간이나 관측도 상한을 넘으면 조회 범위를 좁혀야 하며 일부 행만 받아 전체 자료라고 표시하면 안 됩니다.

### Claude Code 또는 Codex에서 MCP가 연결 안 돼요

1. `claude mcp get korea-stats` 또는 `codex mcp get korea-stats`로 대상 URL을 확인합니다.
2. 등록 후 새 클라이언트 세션에서 다시 도구를 호출합니다.
3. 원격 연결은 사용자 KOSIS 키가 필요하지 않습니다. 클라이언트 자체의 모델 계정 로그인과 MCP 서버 인증은 별개입니다.
4. 로컬 서버라면 빌드 파일 절대경로와 Node.js 20 이상인지 확인합니다.
